# Security decision — CSP and headers (T02)

## Context

The legacy site delivered a strict CSP as a Vercel response header:
`default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'`.

The Astro/Starlight migration necessarily ships inline `<script>` elements
(Starlight's theme initialization, Astro's island runtime, page-level scripts).
A static response header cannot carry per-page script hashes, and blanket
`unsafe-inline`/`unsafe-eval` are forbidden by the packet and by good practice.

## Decision

**HTML pages carry the CSP as a build-generated `<meta http-equiv="Content-Security-Policy">`
tag; the Vercel response header no longer repeats a script/style policy.**

- Astro 7's supported `security.csp` option is enabled in `astro.config.mjs`.
  It computes SHA-256 hashes for every inline script/style it renders and injects
  a per-page meta CSP combining:
  - `default-src 'self'`, `img-src 'self' data:`, `connect-src 'self'`,
    `base-uri 'self'`, `form-action 'none'` (fixed directives), and
  - `script-src 'self' 'wasm-unsafe-eval' <computed hashes>` and
    `style-src 'self' <computed hashes>`.
- Starlight's `is:inline` scripts (theme init, sidebar/modal handlers) and its
  inline `style` attributes are not tracked by Astro's hash computation. Their
  hashes are supplied through the same supported config surface
  (`scriptDirective.hashes` / `styleDirective.hashes` with `kind: "attribute"`).
  The style attributes are allowed via `'unsafe-hashes'` scoped to
  `style-src-attr` only — never a blanket keyword. The hash list lives in
  `src/csp-hashes.json`, generated by `scripts/refresh-csp-hashes.mjs` from the
  built output; `npm run build` builds, refreshes, and rebuilds so the policy
  always matches the artifact. Any framework upgrade that changes an inline
  script fails the `securitypolicyviolation` check in
  `tests/e2e/navigation.spec.ts`, forcing a deliberate hash refresh.
- No `unsafe-inline` or `unsafe-eval` anywhere.

## Hash-file lifecycle

`src/csp-hashes.json` is union-only: hashes accumulate so the two-pass build
converges. This means a removed inline script's hash lingers in the policy
until a manual regeneration. Periodically (notably after removing scripts),
delete `src/csp-hashes.json`, run `npm run build` twice, and review the
freshly computed file before committing it.
- `'wasm-unsafe-eval'` is the single narrow, documented exception: Starlight
  search (Pagefind) executes a WebAssembly search index from same-origin files.
  It is exercised by the search browser tests (T07).
- `frame-ancestors` cannot be expressed in a meta policy (ignored per CSP spec),
  so framing protection is delivered by the `X-Frame-Options: DENY` response
  header in `vercel.json`, which remains for all responses.
- The response header retains `Referrer-Policy: strict-origin-when-cross-origin`,
  `X-Content-Type-Options: nosniff`, and `X-DNS-Prefetch-Control: off`.
- Because response-header and meta policies intersect, repeating a restrictive
  `default-src 'self'` in the header would break the hash-allowed inline scripts.
  The header therefore carries only non-CSP protections; HTML CSP is meta-only
  and validated against the built artifact by tests (`tests/csp.test.ts` asserts
  every emitted HTML page has a meta CSP and that it contains no `unsafe-`
  keywords).

## Why this composition is safe

- Every active policy (meta per page) is at least as strict as the legacy header
  for scripts/styles; hashes are strictly narrower than same-origin for inline
  code.
- Non-HTML responses (assets) get the header protections; they execute no
  scripts.
- Anti-framing is enforced by XFO on every response.

## Tested behaviors

- Page scripts execute under the meta CSP (Playwright: no `securitypolicyviolation`
  events, no console CSP errors) — `tests/e2e/security.spec.ts`.
- Code highlighting uses external stylesheets (`markdown.shikiConfig.inlineStyles:
  false`), so no style-src exception is needed for syntax highlighting.

## Remaining hosted checks (T08, not proof here)

- Verify Vercel actually delivers `X-Frame-Options`, `nosniff`, and
  `Referrer-Policy` headers on the deployed preview.
- Confirm Pagefind search works on the hosted preview with the meta CSP.
- Local tests exercise the policy design with the built artifact; they do not
  certify Vercel's delivered headers.
