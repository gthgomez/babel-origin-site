Babel Desktop is an Electron visual shell for the Babel Harness. The real
work still runs the Babel CLI underneath; Desktop is the window around it.

## Published portable preview (unsigned)

The v0.1.1 GitHub release publishes the Windows x64 portable bundle as a real,
checksummed asset — the builder pins Node 24.13.1 and Electron, verifies
archive SHA256 values, and emits `BUILD.json` plus `SHA256SUMS`. It is
**unsigned**: no code-signing identity, no SmartScreen reputation, no published
`Setup.exe`/installer, and no automatic updater. Verify the ZIP's SHA256
against the release's `SHA256SUMS` before running it. See
[Get Babel](/download/) for the download, checksum, and the supported
source-install path.

## The opening screen is a reference preview

The initial reference session reproduces a supplied screenshot and is
explicitly labeled **REFERENCE PREVIEW**. Its model names, file names,
findings, tool results, and context numbers are fixtures — not facts about an
actual Babel run. After you connect a project, a task runs the real CLI and
the center panel shows that run.

## Bundled runtime and behavior

The portable preview includes the Desktop shell, the authoritative CLI,
immutable prompt assets, production dependencies, and a pinned Node runtime —
no separate npm install needed. Setup notes:

- Credentials are configured by you in a `.env` file in the configuration
  directory shown in Setup. Desktop does not import credentials from other
  apps or checkouts.
- Desktop does not start Docker, change Windows policy, or switch to
  unrestricted host execution. The default `safe_repo` profile still applies.
- UI preferences live under `%APPDATA%\babel-north-star-desktop`; CLI state
  lives under the bundle's `engine` directory. Nothing writes back to bundled
  resources.

## Explicitly unqualified

Per the product's own installation notes:

- No code-signing identity, SmartScreen reputation, automated updater,
  Start Menu registration, or uninstaller.
- Active model-task shutdown on quit is not qualified.
- Cross-version profile migration is not qualified.

Do not disable Windows security settings to run an unsigned preview.
