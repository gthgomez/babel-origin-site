Plan mode produces a reviewable plan before any mutation happens. Use it when
you want an explicit gate between "what Babel intends to do" and "what it
actually does".

```powershell
node .\babel-cli\dist\index.js plan "Split the auth module safely"
```

## Behavior and boundaries

- Plan mode does **not** load the full governed pipeline; it runs the plan
  path and stops at a plan artifact, with interactive apply on approval.
- The plan is produced for your review — reading a plan on this website or in
  the CLI does not execute anything. Approval happens in your session, not
  anywhere else.
- Like chat, plan shares the unified execution kernel and the same
  execution-profile isolation rules.

## When to choose Plan instead of Chat

- The change spans several files or subsystems.
- You want to check scope before any write happens.
- You are working in a repository where mutation needs review first.

For riskier work that also wants adversarial review and verification
structure, see [Deep](/docs/using-babel/deep/). Plan is not more reliable than
Chat for ordinary tasks — it is a different gate.
